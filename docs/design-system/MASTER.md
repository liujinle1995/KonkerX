# 幻之分身 · 设计系统（Master）

> 本文件是界面层的唯一真理源。改动颜色、间距、触摸目标、反馈策略，先改这里，再改代码。
> 页面级例外写到 `pages/<页面>.md`，只记录与 Master 的差异。
>
> **动效（时长、缓动、逐条转场）不在这里**，见同目录 `MOTION.md` —— 那份文件按
> `compose-motion-design` 技能的方法产出，管的是「界面怎么动」。

**来源**：`ui-ux-pro-max` 技能（v2.15）生成的基线 + Android/Material 3 适配。
**生成器结论**：Minimalism & Swiss Style（企业工具、仪表盘、专业工具向），性能成本 low，
无障碍风险 low，要求 `contrast-text-4.5 / keyboard / visible-focus / reduced-motion`。

> **3.6 起基线换到 Material 3 Expressive**（Material 库 1.12.0 → 1.14.0）。
> 主题基类为 `Theme.Material3Expressive.DayNight.NoActionBar`。下面凡是提到
> 「M3 默认」的地方，取值都由这套基类提供。品牌色未变。

## 0. 对生成器输出的取舍

技能按 Web 出模板，直接套会错，逐条判定：

| 生成器给的 | 采纳？ | 处理 |
|---|---|---|
| 风格：Minimalism & Swiss（留白、几何、强层级） | ✅ | 已基本符合，继续强化 4/8dp 节奏与留白 |
| 配色：Navy `#1E3A5F` + 绿 `#059669` | ❌ | 应用已有实装品牌色 `#3D5AFE`，换色收益为 0；改用 M3 语义色 |
| 字体：Outfit / Work Sans | ❌ | 中文环境无对应字形，Android 系统字体（Roboto/思源黑）才是正确选择 |
| 字号：base 16px | ✅ 换算 | 正文 14sp（M3 bodyMedium），标题 ≥ 16sp，绝不出现 < 12sp 的信息性文字 |
| 间距：px 栅格 | ✅ 换算 | 4/8dp 栅格，见 §3 |
| `cursor-pointer` / hover / 150–300ms | ❌ | 触屏无 hover；改为 ripple + `stateListAnimator`，按压反馈 80–150ms |
| 断点 375/768/1024/1440px | ✅ 换算 | 用 `-sw600dp` ＋ `Screen.columns()`，已验证手机 1 列 / 平板 2 列 |
| 图标用 SVG 不用 emoji | ✅ | 全量 Material 24dp 线性填充族，禁止 `⋯`、`☰` 这类字符充当图标 |
| 对比度 4.5:1 | ✅ | 实测见 §2，全部达标 |
| 焦点可见 | ✅ | 已用 `?attr/selectableItemBackground` + `focusable`，TalkBack 可达 |
| reduced-motion | ✅ 部分 | 索引气泡/动画均 ≤ 200ms 且非装饰性循环，保留 |

## 1. 颜色（语义 token，禁止在布局里写死 hex）

一律用主题属性，不写 `@color/xxx`（品牌色与徽标色除外）：

| 用途 | Token | 亮色取值 | 深色取值 |
|---|---|---|---|
| 品牌 / 主操作 | `?attr/colorPrimary` | `#3D5AFE` | `#A8B4FF` |
| 主操作上的文字 | `?attr/colorOnPrimary` | `#FFFFFF` | `#0A1120` |
| 页面底色 | `?attr/colorSurface` | M3 默认 | M3 默认 |
| 正文次要文字 | `?attr/colorOnSurfaceVariant` | `#49454F` | `#CAC4D0` |
| 描边 / 分割线 | `?attr/colorOutlineVariant` | M3 默认 | M3 默认 |
| 选中行底色 | `?attr/colorSecondaryContainer` | M3 默认 | M3 默认 |
| 风险徽标文字 | `@color/badge_warn_text` | `#A15C00` | `#FFC46B` |
| 风险徽标底/边 | `@color/badge_warn_bg` / `_stroke` | 琥珀 10%/36% | 琥珀 15%/36% |

> **关于「不要在 xml 里写死 hex」**：`res/values/colors.xml` 与 `values-night/colors.xml`
> **是**令牌的定义处，写在那里是规定动作，不违规。违规的是在 `res/layout/**` 或
> Kotlin 里直接写 `#RRGGBB`。同理，矢量图标里的 `android:fillColor="#FFFFFF"`
> 配合 `android:tint="?attr/colorControlNormal"` 是标准写法 —— 真正的颜色由 tint 决定。

> 已弃用：`?android:attr/textColorSecondary`（框架色，深浅色切换不完全受 Material 3 控制）。
> 新代码一律 `?attr/colorOnSurfaceVariant`。

## 2. 对比度实测（WCAG 2.1，正文阈值 4.5:1）

| 组合 | 比值 | 判定 |
|---|---|---|
| 品牌 `#3D5AFE` on `#FFFFFF` | 5.13:1 | ✅ |
| 徽标文字 `#A15C00` on `#FEF7E9`（琥珀底叠白） | 4.87:1 | ✅ |
| 深色品牌 `#A8B4FF` on `#141218` | 9.42:1 | ✅ |
| 深色徽标 `#FFC46B` on `#2A2110` | 10.09:1 | ✅ |
| 次要文字 `#49454F` on `#FFFFFF` | 9.34:1 | ✅ |

## 3. 尺寸与节奏（4/8dp 栅格）

| Token | 值 | 用途 |
|---|---|---|
| `space_1` | 4dp | 图标与文字、行内微间距 |
| `space_2` | 8dp | 组件内部、卡片之间的最小间隔 |
| `space_3` | 12dp | 卡片内边距、列表外边距 |
| `space_4` | 16dp | 页面左右留白、条目内边距 |
| `space_5` | 24dp | 分组之间 |
| `space_6` | 32dp | 空态、页脚 |
| `touch_min` | 48dp | **所有**可点区域的最小边长（Android 硬指标） |
| `touch_gap` | 8dp | 相邻可点区域的间距 |
| `icon_lg` / `icon_md` / `icon_sm` | 24 / 20 / 16dp | 主图标 / 列表尾标 / 行内小图标 |

**圆角**（`shape.xml`，3.6 新增）：`radius_xs` 8 / `radius_sm` 12 / `radius_md` 16 /
`radius_lg` 20 / `radius_xl` 28 / `radius_pill` 9999。相邻档至少差 4dp —— 差得出来才
看得出是设计。胶囊用 9999dp 而不是具体值，控件改高度也不会塌成圆角矩形。

**列数**（`integers.xml`）：`settings_columns` 手机 1 / ≥840dp 时 2。

禁止出现 1dp、2dp、14dp、18dp、26dp 这类随手值。
文字上限：标题 1 行 `ellipsize=end`；包名 `ellipsize=middle`（保住前后缀）；任何截断都要有第二条可达路径（点进详情/菜单看全）。

## 4. 组件约定

### 列表条目
- 最小高度 64dp，`foreground="?attr/selectableItemBackground"` 提供 ripple（80–150ms）。
- 图标 44–48dp、`contentDescription="@null"`（旁边有文字，属装饰，不能占无障碍焦点）。
- 主标题 1 行 + 副标题 1 行；徽标紧贴标题右侧，**颜色不能是唯一信息载体**（必须带文字）。

### 图标按钮
- 尺寸 48×48dp，`contentDescription` 必填，语义化描述动作（"更多操作"而非"三个点"）。
- 只用矢量图标，禁止 `⋯`、`⋮`、`➕` 等字符代替图标。

### 空态
- 必须三件套：图标 + 一句现状 + **一个动作**。只写"还没有"是反模式。

### 破坏性操作
- 卸载 / 删除记录 / 覆盖重建：先弹确认，说明后果与可逆性，确认按钮用 destructive 语义。
- 不可逆动作的确认文案必须写明"数据会怎样"。

### 长任务（>300ms）
- 立刻给阻塞式反馈（进度 + 说明文字），期间禁用入口，避免重复提交。
- 完成后再给结果提示；失败要给下一步建议，不能只报错。

## 6. 已知不做（有意为之）

- **不做品牌换色**：现有 `#3D5AFE` 已达标且用户已习惯，改色属于无收益的美化。
- **不引入第三方字体**：中文正文字体包会让 APK 涨 3–8MB，工具类应用不值。
- **不做 hover / cursor 态**：触屏平台无此语义，仅保留 ripple 与 focus。
- **不做底部导航**：一级页面只有"分身列表 / 设置"，FAB + 溢出菜单已足够，加 tab 反而多一层。

## 7. 响应式（3.7）

三档断点，与 Material 3 的 window size class 一致，实现在
`ui/adaptive/WindowSizeClass.kt`：

| 档位 | 宽度 | 导航 | 主页 | 选应用页 | 设置页 |
|---|---|---|---|---|---|
| COMPACT | < 600dp | 底部玻璃胶囊 | 单列列表 | 1 列 + 底栏 | 单列 |
| MEDIUM | 600–839dp | 底部玻璃胶囊 | 单列列表（卡片变宽） | 1 列 + 底栏 | 单列 |
| EXPANDED | ≥ 840dp | **左侧栏 220dp** | 2～3 列网格 + 运行概览摘要 | 2 列瀑布流 + 右 276dp 已选栏 | 左右两栏 |

**3.7 推翻了 3.6 的 list-detail 双栏。** 设计稿给的是「左栏导航 + 右侧 2 列卡片
网格 + 下方运行概览」：平板上有整块屏幕的宽度，用「列表 + 详情」会把一屏切成两半、
两边都不够用；而把分身铺成网格，一屏能同时看清五六个分身的状态，这才是一眼想知道的。
详情仍在点击后单独打开。

**为什么导航形态在运行时判断，不用 `layout-sw840dp` 资源限定符**：资源限定符看的是
最小宽度（sw）。平板横屏拖进分屏后，实际窗口宽度可能掉到 600dp 以下，但 sw 没变 ——
按资源给侧栏会占掉 220dp，内容区只剩一条。判断依据用 `Configuration.screenWidthDp`
（当前窗口可用宽度），配置变化会触发 Activity 重建，重建后自然拿到新值。

**列数不写死。** `gridColumns(内容区宽度)` 从「能塞下几张最小 340dp 的卡」反推，
1024dp 窗口给 2 列（每列 370dp）、1280dp 给 3 列。写死 2 列在桌面窗口里会得到
两张各 600dp 宽、右边空掉三分之一的卡 —— 那不是还原设计，是没适配。

**侧栏是固定 220dp，不按比例。** 侧栏里最长的一行是「5 个分身 · 已占用 1.3 GB」，
量下来 190dp 出头。按比例的话 1024dp 给 22%、1600dp 就给 352dp，多出来的 130dp
里什么都没有，只是把内容区无端压窄。

**侧栏配色与页面底的关系**：浅色下侧栏 #F0F0F5 比页面底 #F2F2F7 略暗，深色下
#1C1C1E 比页面底 #000000 略亮。看着像随手取的，其实是同一个原则的两面：
侧栏要比内容区「退后一层」，而"退后"在亮底上表现为更暗、在暗底上表现为更亮。

**平板卡片 112dp 高、8dp 行距、14dp 列距**（手机是 88dp / 20dp 行距）。行距比列距
小很多是有意的：宽屏上横向并排的两张卡需要「分开」，纵向相邻的几张需要「连成一片」，
否则每张卡都像一个孤立的方块，扫视时找不到列的连续性。

## 8. 关于验证器告警的说明

跑了 `mobile-app-uiux-pro-max` 自带的 6 个验证器，结论需要人工判读：

- **`COL-TOK` 23 条 error 全部是误报**。它按 Flutter / React 的约定扫，认为颜色必须
  引自某个 tokens 文件；而 Android 的 `res/values/colors.xml` **就是**那个 tokens 文件，
  矢量图标的 `fillColor="#FFFFFF"` + `tint="?attr/..."` 也是标准写法。
  已逐条核实：`res/layout/**` 与 Kotlin 里**没有**任何硬编码颜色。
- **`STATE-COV` 126 条 warning 基本是误报**。它按文件逐个要求 7 种状态，连 drawable
  和 adapter 都算一个文件。本应用**完全离线**，没有网络请求，"offline" 不适用；
  权限被拒的状态在确实需要权限的地方是有的（使用情况访问、安装未知应用）。
- 真实命中并已修复的两条：**RTL 下 `setPadding` 把相对方向固化成物理左右**、
  **6dp / 2dp 不在 4/8dp 栅格上**。

后续再跑验证器时，请以这三条判读为准，不要为了把分数刷上去而在 colors.xml 里
插抑制注释 —— 那只会让令牌文件变得难读。。

## 9. 运行概览（3.8）

这一页与主页/设置页不是同一个信息结构：主页是「一串同级对象」，运行概览是
「一组指标 + 一组对象 + 一组解释」。所以它的节奏也不一样。

| 项 | 手机（12 稿） | 平板（13 稿） |
|---|---|---|
| 行高 | 76dp | 76dp |
| 行内图标 | 40dp / 圆角 10dp | 40dp / 圆角 10dp |
| 行间距 | 8dp | 8dp |
| 卡片圆角 | 12dp | 12dp |
| 统计卡 | 92dp 高，间距 8dp | 103dp 高，间距 8dp |
| 右栏 | 无 | 230dp 固定，与列表隔 16dp |

**行高 76dp 比主页的 88dp 矮一档，是量出来的不是估的**：稿面手机 78dp、平板 74dp。
取 76 是两个形态的折中 —— 同一个组件在两种设备上差 4dp，只会让人以为哪边没对齐。

**卡片圆角 12dp 而不是主页的 16dp**（稿面实测 48px 半径）。行变矮之后 16dp 的圆角
会吃掉两侧的直线段，卡片看起来像个胶囊。

**状态文字的位置随宽度变，文案也随页面变**：

- 手机：右侧「体积 + 状态」两行（`512 MB` / `未运行`）；
- 平板：状态并进副标题（`最近启动 · 12 分钟前 · 未运行`），右侧只留体积 ——
  五个数字在宽屏上能对齐成一条竖线，扫起来是五个数而不是五组字；
- 「从未启动」不并状态：副标题已经说了这件事，再补一句「未启动」是同一句话说两遍。

同一个分身，主页写「运行中」、这里写「前台运行」。这不是文案没统一：
主页那张卡回答「它现在能不能点」，这一页回答「它此刻活着吗」。状态的判定顺序
只有一处（`resolveCloneStatus`），措辞各页自定。

**分色占用条**：段宽按占用比例分配，段间留 1.5dp。不留缝时，蓝接靛、橙接粉
这种相邻色会连成一条渐变，读不出「这是五个东西」。段色按位置取（`HzSegmentColors`），
不按分身身份 —— 颜色跟着人走，用户每次进来都要重新认一遍。

**右栏面板正文 12sp / 16sp 行高**（正文 13sp 会让「StorageStatsManager 按包精确统计」
多折一行）。另有一个 Compose 的坑写在代码里：`.width(230).padding(...)` 的 230 是外框，
内宽只剩 190 —— padding 必须写在 width 前面，否则面板里所有文字都会多折一行。

**这一页刻意没有设备内存条**。非 root 设备读不到别的 UID 的 RSS，那张卡在真机上
大概率是空的；保留它就等于每次打开页面都先说一次"我读不到"。内存只剩右栏一条
橙色说明：橙色是因为它是**限制**而不是说明，用户看到「没有内存数据」的第一反应是
"是不是坏了"，得先让他知道这是系统不给。

## 10. 选应用页（3.9）

这一页是全流程里唯一「上千行、可搜索、要勾选」的页面，也是全应用最后一个还留着
上一代 Material 界面的入口。它的难点不在还原，在两件事：**一屏塞得下多少个应用名字**，
和**平板上勾完之后去哪儿确认**。

| 项 | 手机（05/07 稿） | 平板（32/33 稿） |
|---|---|---|
| 搜索框 | 44dp 高，圆角 12dp | 44dp 高，圆角 12dp |
| 分段控件 | 32dp 高 | 32dp 高 |
| 行卡 | 72dp 高，圆角 12dp | 96dp 高，圆角 12dp |
| 行内图标 | 40dp，圆角 10dp | 44dp，圆角 10dp |
| 卡片左右边距 | 16dp | 24dp |
| 列数 | 1 列 | 2 列瀑布流 |
| 右栏 | 无 | 276dp 固定，与列表隔 12dp |
| 底部 | 玻璃条 64dp | 无（动作在右栏） |

**行卡比主页矮一档（72 < 88）**：主页卡片一行要装「名字 + 副标题 + 状态」三段信息，
这一页是「名字 + 包名」两段，再给 88dp 就是在下面留一条空白。副标题的构成也随宽度变：
手机是 `包名 · 体积`，平板只留 `包名` —— 平板一行更宽，加体积会让右边界参差不齐，
而体积在这个页面根本不是决策依据（选应用看的是"哪个 App"，不是"多大"）。

**平板用瀑布流而不是等高网格**。这一页的分组是按首字母分的，A 组 3 个、S 组 14 个，
等高网格会把短组撑出大片空白，一屏只能看四五个组。`LazyVerticalStaggeredGrid` 让
短组自然填补，实测一屏能扫到 9 个组标题。

**平板一进来就是勾选态，手机要点「多选」**。这不是交互不一致，是这两种设备上「为什么
打开这一页」不同：手机上多是「我想再建一个分身」，一步到底；平板上打开这一页时右栏
就在那儿，空着才是异常。所以平板的 `selectionMode` 初值为 true，取消勾选后右栏给空盒子
+ 一句指引，而不是收起整个面板 —— 面板消失会让右侧内容区突然变宽、列表跳动。

**已选清单的数据源必须是 `selected` 而不是 `sections`**。第一版从当前可见的
`sections` 里捞已选项，切到「已分身」筛选后，之前勾的未分身应用就从右栏消失了 ——
勾选状态和可见列表是两件事，清单要按勾选顺序独立维护（`LinkedHashMap` 保序）。

**步进器 56×28dp 是不合规的，知道且保留**。Material 的触摸目标下限是 48dp，这里
加减各 22dp。原因：右栏要在一屏里放下 5～6 行已选应用，每行 48dp 会把清单撑到
需要滚动；而这两个按钮是「同一行的微调」，不是独立入口，误触代价只是多一份/少一份，
可以立刻改回来。这是一个有意识的取舍，**不是漏了**。手机上没有步进器（一份走完全程）。

**右栏的应用名允许折两行，不截断**。236dp 的卡片扣掉图标、间距、步进器只剩约 114dp，
「HuanZhi 测试目标」这类中英混排必然溢出。这一栏唯一的职责是让人确认"我勾了哪几个"，
名字截成「HuanZhi 测…」等于没说；折行最多用掉两行的竖直空间，而 88dp 的行高容得下
（标题两行 44 + 间距 3 + 副标题 18 = 65）。左栏列表不受影响，一行够宽，仍按设计稿单行。

**分片安装包在扫描阶段就判定**，用 `ApplicationInfo.splitSourceDirs` 非空。第一版是
等到点「下一步」建包时才由 packer 报错，用户勾了五个才发现其中一个不行 —— 现在它在
列表里就是一个不可选的灰色行，副标题直接写「分片安装包，暂不支持」，且只有它会被
排除在勾选之外（整组应用不受影响）。

**分组排序把 `#`（非字母开头）固定放最后**。`compareBy({ if (it == '#') 1 else 0 }, { it })`
—— 按字典序 `#` 会排在所有字母前面，一进页面第一眼看到的是「12306」「360」这类，
既不是用户想找的，也不像"开头"。放在末尾它就是"其他"，符合预期。

**空态按筛选分三套文案**。搜索无结果说「换个关键词」，「已分身」为空说「还没有建过
分身」，「不支持」为空说「都支持」—— 一句通用的「暂无数据」会让用户以为列表加载失败。

**勾选状态必须活过 Activity 重建**。这一页的「已勾选 + 每项份数 + 关键词 + 筛选」都是
Activity 里的普通字段，转屏或切深浅色会重建 Activity，不写进 `Bundle` 就全没了 ——
用户勾了五个应用，系统发一条夜间模式广播就清零，这不是可以接受的代价。存的是
包名与份数（不是 `AppEntry` 对象）：扫描结果重建后会自然再有一份，存对象既撑大
`Bundle`，也会因为应用在这期间被卸载而对不上。
